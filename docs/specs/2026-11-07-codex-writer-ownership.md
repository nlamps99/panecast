# 已有写入进程的 Codex 会话

`thread … already has an active writer` 表示另一个 Codex 进程已持有该会话的写入锁。
当前轮次完成、历史能读取、或桌面服务在线，都不代表原进程已经释放写入权；一个仍
打开的空闲 CLI 也会持有它。此前的新建/共享服务验证未覆盖独立进程已占用旧会话的情况。

本次处理：

- 原生恢复失败时识别该错误，返回 `thread_owned_elsewhere` 及明确的中文说明。
- 复用当前服务已订阅的会话，避免重复恢复。并发恢复时先重新确认本服务的加载状态。
- 原生 Codex 的锁获取结果是最终依据；历史里遗留的 `inProgress` 不再阻止正常恢复。
- 只读查询本机 writer 文件的打开进程和已知终端变量，不删除、修改或强行释放锁。
- 对能确认的 cmux/tmux 原终端，网关在对应来源启用且有操作权限、目标仍存在时返回
  带来源命名空间的导航目标。未授权、只读、已撤销或无法验证的目标不返回。
- 手机显示占用说明，提供「去原终端继续」「重试继续对话」「从历史新建」。
  原终端入口使用既有终端连接，保持原进程及任务；新建分支会创建不同的对话。

真实 Codex 双进程测试复现了同一句原始错误：第一个进程已结束轮次但保留会话，
第二个进程无法恢复。验证错误映射、原进程不被抢占，以及原进程释放后恢复同一 ID。
授权回归测试覆盖原终端导航的只读和撤销条件。客户端测试、类型检查及 lint 通过。

本机只读探测已验证能找到终端中打开的会话并解析到其原 cmux surface。
已有手机配对不变；新的占用状态和直达按钮需要更新客户端。
