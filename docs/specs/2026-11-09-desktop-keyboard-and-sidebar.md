# 桌面实体键盘与侧栏布局

## 问题与根因

侧栏的窗口切换使用横向 ScrollView。React Native Web 的滚动容器默认同时允许
flexGrow 和 flexShrink，它与工作区列表共享纵向空间，在列表较长时会被压缩到小于
内部 34 px 按钮的高度，截图中只有按钮上半部可见。WindowChips 现在声明自己的
固定行高与不伸缩约束，侧栏控制区不参与收缩，工作区列表承担剩余空间的滚动。

桌面复用了手机的虚拟按键栏，默认整行输入；Web 输入组件只处理 Enter 和退格，
没有把物理键盘的导航键和 Control 组合键送入已有的终端输入队列。

## 行为

- 桌面终端默认直接输入，隐藏手机按键栏和「命令/逐字」切换器。桌面输入偏好独立，
  用户仍可选择「编辑命令」暂存整条命令，切回后草稿保持。手机原有输入行为保留。
- 实体键盘的 Tab、Shift+Tab、方向键、Home/End、PageUp/PageDown、Esc、删除、
  F1–F12 和 Control 组合键走已有有序输入队列。监听仅位于获得焦点的输入区。
- 输入法组字期间不截获按键、不发送拼音片段；提交中文后只发送一次。Command
  快捷键、Option 产生的文字和死键交给系统，复制粘贴及窗口切换不被转发。
- 点击终端文字可激活输入；选择终端文字时保留选择，以供本机复制。
  对话模式继续编辑草稿，Enter 发送、Shift+Enter 换行。
- 文件拖放与图片粘贴沿用 0.2.3 的上传逻辑；直接输入模式将路径写入远端输入行，
  仍由用户按 Enter 提交，并显示符合当前模式的上传提示。
