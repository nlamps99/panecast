# 终端页对话模式复查

问题集中在终端页“对话”模式，而非独立连接源页面。保留进入本轮前尚未提交的
writer ownership 等修改；本轮开始时的快照单独保存在本机临时目录。

已复现并修复：

- 对话解析只过滤极少数前缀，子代理通知、下发消息和结构化内部来源可被标成“你”。
  新解析先处理来源和完整控制封装，再截断预览；客户端兼容过滤旧网关数据。
  内部事件在选择 canonical 格式和计算运行状态前按主 thread ID 过滤。
  普通文字提到子代理、代码块中的示例、环境信息后附带的真实用户消息仍保留。
- 问答回执原始 XML/JSON 转为问题和回答；命名空间化的同步／异步提问正常显示。
- `final_answer` 已完成回复现在结束等待状态，Claude 压缩摘要不作为用户消息。
- 识别当前终端带选项和操作提示的提问，在聊天中提供选择卡片。选项点按只移动
  高亮，用户再点“确认当前选择”提交；支持上下项、多选空格、下一题和取消。
  动作串在同一输入队列中发送，检查终端目标与当前画面；迟到画面、切换终端、
  只读权限与未知发送结果均不得导致自动确认或重发。
- 对话模式回车换行、按钮提交。网关确认 cmux 提供 `terminal.paste` 后发布能力，
  客户端通过原输入队列将整条消息括号粘贴并提交一次；旧网关保留兼容路径。
  当前终端有待选对话框时拒绝普通草稿发送，保留草稿并提示先处理选项。

来源语义参考：官方 Codex App Server 文档
https://learn.chatgpt.com/docs/app-server ，其中 thread/list 的 sourceKinds 明确区分
子代理，thread 与 item 事件使用 threadId 定位。具体本地 rollout 格式以只读观察
和脱敏 fixture 为依据，未向生产会话发送测试提示词。

验证：共享过滤用例覆盖客户端和网关；客户端全部 635 项通过，网关 105 项通过、
1 项按环境跳过。真实隔离 cmux 原始输入程序收到完整多行括号粘贴和单次 Enter。
原生界面验收使用 client/e2e/terminal-chat 的独立模拟器与本机替身服务。

原生 XCTest 两条场景均通过：选项高亮与提交分离、多行单次发送、内部消息不可见，
以及工具折叠、终端切换、90 轮历史连续回溯、模式重开恢复。另补旧网关的多行草稿
保护测试，避免未支持括号粘贴时逐行提交。打包中发现隔离复制错误排除了本地
TerminalInput 原生模块，已修正并重新生成；发布包必须核对该模块后才能上传。

对当前 20 个 Codex 终端做了只读解析对照：均绑定主会话；最近记录中的 8 处问答
回执变为可读文字，1 处完成状态得到修正。这批最近记录没有命中子代理过滤，子代理
封装和不同 thread 的串入由专门回归样例验证，不声称已复现用户所有原始记录。
