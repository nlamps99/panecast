# cmux 监工与微信任务入口

微信之前要求先选择一个终端，再把每条文字直接送过去。监工模式把微信用户消息交给
一个可见的本地 Claude Code 会话，由它依据任务目标定位执行者、下达工作并核查结果。
执行者保持各自原有的会话和上下文，工具过程不直接发送到微信。

核心模块位于 `relay-tmux/supervisor/`，通过注入的 gateway/launcher 接口使用终端能力。
宿主适配为 `relay-tmux/src/hub/supervisor.mjs`，微信只负责用户请求与明确报告的交付。
这次不涉及移动客户端或 cmux 源码修改。

## 运行与持久化

- `panecast supervisor start` 创建并选中「监工」工作区；首次 Claude 信任/登录在该窗口完成。
  窗口保持可见，不因等待超时关闭。MCP 工具完成注册后才投递首个唤醒。
- 监工只启用自己的 MCP 工具；编码工作在执行者中完成。现有任务登记原终端，新的
  执行会话限定在已经发现的本机项目目录。
- SQLite 保存任务、输入、投递操作、证据事件与通知。数据库、凭据、私有 Unix socket
  都只允许本机当前用户访问。网关重启不重复创建监工，也不重发结果未知的指令。
- 自建执行者的会话 ID 来自启动参数和私有登记表。现有会话使用 cmux 终端列表中的
  精确绑定。写入前同时验证目标和编码进程，避免 CLI 退出后把指令送到 shell。

## 行为约束

用户请求与执行者观察分开记录。派工需引用真实用户请求或同一任务的结果事件，单个
任务自动跟进最多三次。暂停任务取消尚未发送的指令；暂停监工不会把微信消息回退到
以前选择的原始终端。

指令发送前落盘 `attempting`。回执未知时进入 `unknown`，通过后续真实用户输入记录
匹配才能自动确认接收；否则保留状态供人工核查，避免换操作 ID 重发。操作键由触发
事件、任务和指令内容确定。

执行者的 final 进入待验收状态。监工需要引用该任务最近执行后的实际结果事件，才能
标记完成。问题选择需有用户答复，并在按回车前重新核对问题与高亮选项。微信只接收
监工明确发布的用户答复、待处理问题和验收完成结果。

## 验证

- 网关完整测试：156 passed，3 个按环境跳过。
- 监工专项：17 项通过；同时在实际分发的 Node 22.23.4 下运行。
- 真实 Claude 监工与真实 Claude 执行者的闭环通过：准确找到指定验证终端，发出一条
  指令，会话记录确认收到，执行者返回指定随机标记，监工引用实际结果并将任务验收为 done。
- 验证工作区保留供查看。首次信任由用户完成。微信路由通过隔离通道测试，真实执行闭环
  的报告使用测试收件箱，不向用户发送测试内容。

测试位置：`relay-tmux/test/supervisor.test.mjs`、`weixin.test.mjs`、`weixin-hub.test.mjs`。
真实结果保存于本机 `/tmp/panecast-supervisor-worker-qa-result.json`。
