# 终端快捷键执行结果不可见

用户反馈手机快捷栏的 Ctrl + ↑ 没有生效。实际通过客户端会话和正在运行的 cmux
relay，在隔离终端的原始输入读取程序中收到 `ESC [ 1 ; 5 A`，字节为
`27,91,49,59,53,65`；普通方向键和其他 Ctrl 方向键同样正确。

真正复现的客户端问题是：浏览历史后点击快捷键会发送到远端，但 `browse.frozenRows`
仍保留旧快照。即使远端更新画面，手机也不显示执行结果。全屏应用虽保持实时更新，
若手机正在当前画面的顶部阅读折行，输入位置仍在屏幕外。

显式发送按键、文本或命令时，现在取消历史阅读与未完成的位置恢复，并通知视图回到
当前输入位置。视图忽略回到底部之前迟到的原生滚动事件，避免立即再次冻结。离线
失败保留当前阅读内容；只读来源禁用快捷键。

测试包括真实 KeyBar → TerminalSession → TerminalView 的组合回归、Ctrl 开关
叠加、连续按键、全屏应用阅读位置、断线和初始画面前恢复阅读。

原生 XCTest 位于 `client/e2e/terminal-keys/`，使用独立模拟器和 loopback 服务。
旧版安装包中，真实滑动进入历史、点击 Ctrl + ↑ 后，服务端记录已收到一次正确按键，
但 `CTRL_UP_RECEIVED_1` 未显示，测试按预期失败。

相同模拟器安装修复版后，同一原生测试通过：浏览历史后第一次点按能看到远端返回，
历史提示消失，第二次点按也能看到新的返回。服务端分别记录正确的一次、两次按键。
客户端 562 项测试、类型检查和 lint 均通过；iOS 归档与导出成功。
