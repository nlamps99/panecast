# Codex 手机对话流程

手机的 Codex 来源现在提供「新建对话」和「继续对话」。新建时选择电脑上已发现的
项目目录并可填写名称；电脑端 `projects` 配置可以限制候选项目。未加载的历史会话
只有用户明确点击继续才恢复。若它最后一轮仍在执行且不属于当前服务，直接恢复会拒绝，
用户可以选择「从历史新建」分支为另一条对话。

此前缺少入口的原因：新建按钮依赖未配置的固定 `cwd`，历史会话则只有只读说明。
这两处已改为完整的手机操作流程。

长会话使用虚拟列表，首屏按 5 轮分页；每轮保留用户消息、回复和最近 30 条可见工具记录。
连续的命令、文件修改和外部工具调用默认收成一条摘要，点击展开、再次点击收起。
用户消息、回复和计划按原顺序显示；正在执行和失败数量保留在摘要上，任务错误及审批请求
继续直接显示。展开的工具仍逐条使用虚拟列表，不会一次渲染整段命令输出；实时更新和
加载较早消息会保留本次会话内已选择的展开状态。
命令输出、文件 diff、多段文字都有传输和显示上限，并显示片段或省略提示。来自旧 relay
的空字段或超长内容也会在客户端解析时处理，避免直接当作有效渲染数据。

验证于 iOS 26.5 的独立 `Panecast Codex QA` 模拟器：

- XCTest 实际点击长会话、滚动、返回，连续重复三次。
- 工具默认折叠、点击展开和收起、正文回复可见、刷新后保持折叠，已在独立的 `Panecast Tools QA` 模拟器通过操作验证。
- 继续已有会话，输入消息、发送并显示回复。
- 选择项目、新建有名称的会话，再次发送并显示回复。
- 分页历史和旧 relay 的整段大历史两种响应均通过。整段测试数据为 20 轮，每轮 80 条工具记录。
- UI 测试使用本机测试 broker/relay，回复为明确标注的模拟数据；不调用真实账号的模型。
- 真实 Codex 二进制配合本地模型替身的集成测试验证共享回合、追加、停止、新建命名会话。
- 正在运行的公网网关已验证新建/继续能力、12 个可选项目，以及真实长会话的分页读取。

没有取得用户真机那次闪退的崩溃报告，因此不能断言它与长历史渲染完全同因；新版上述
模拟器流程未出现闪退或未捕获 JS 异常。客户端测试、类型检查和 lint 均通过。

测试和复现方式见 [模拟器 UI 测试](../../client/e2e/codex-ui/README.md)。服务端可独立升级；
新按钮、项目选择和虚拟列表需要更新手机客户端，原配对可以沿用。
