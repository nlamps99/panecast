# Mac 桌面关闭入口

Mac 桌面使用 WKWebView，但终端关闭确认先进入 `Platform.OS === 'web'` 分支，
调用未实现的 `window.confirm`，绕过已有的 Tauri 原生弹窗。已有回归测试确认：
原生弹窗返回确认时，旧路径仍返回 false。侧栏缺少关闭操作，终端标签只能长按，
最后一个终端始终被拒绝。

0.2.6 为终端标签、侧栏终端和工作区、工作区列表提供可点击的 ×。桌面关闭确认使用
已有原生 dialog IPC，取消为默认操作；浏览器和手机保留各自的确认实现。关闭当前
终端后切换到相邻终端。最后一个终端会提示关闭整个工作区，再发送 workspace.close。
确认后重新检查权限、连接和目标；新出现的终端不在旧确认范围内。

Mac 菜单新增中文“文件 → 关闭窗口”，保留原生 Command-W 动作、Dock 重新打开
和 Command-Q 退出行为。客户端实体键盘的 Command-W/Q 不会被转发到远端。

验证覆盖原生桥接确认、取消和异常、只读来源、最后终端、目标变化，以及真实组件
按钮的点击和选中状态。客户端类型检查与 lint、Rust Clippy、4 项 JS 桥接测试、
8 项 Rust 测试通过（生产账号与系统钥匙串两项显式测试未运行）。安装器验证包括
校验失败不覆盖、运行中应用保护、安装回滚、旧版备份和路径兼容；签名与 DMG 检查通过。

Mac 原生 XCTest 使用独立 bundle ID 和静态测试页，不读取登录信息或连接实际终端。
该环境的测试 runner 停在 dyld 启动阶段，尚未执行测试；已停止并清理测试进程，
没有将红色关闭按钮、Command-W 和重新打开的原生点击验收计为通过。

本机 /Applications/Panecast.app 已由 0.2.2 更新为 0.2.6；安装前后加密凭据文件
逐字节一致。旧应用备份与本机安装回执保存在安装记录中。没有发布下载站或重启网关。
